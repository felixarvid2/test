# Tower Merge – Last Stand

A portrait (9:16) mobile-first merge tower defense and roguelite for YouTube Playables. It also runs in any browser.

Built with Phaser 3.90, TypeScript, Vite and vitest.

## How it plays

Enemies walk a serpentine path toward your castle at the bottom of the screen. Flyers cut diagonally. You have 12 tower slots, 4 of them open at the start. Buy rolls a random tower from your loadout into an empty slot. Drag a tower onto an identical one (same type and level) to merge them into a higher level, up to level 5. Locked slots can be bought with gold. After each wave you pick 1 of 3 upgrades, and random events appear between waves. Every 5th wave is a boss: Goblin King (wave 5), Stone Golem (wave 10), Dragon (wave 15), then the bosses loop with scaling. Four abilities can be used during a run: Meteor and Repair from the start, Freeze after a best wave of 5, and Frenzy after a best wave of 10.

## Content

| Type | Count | Notes |
|---|---|---|
| Towers | 8 | 5 levels each. Levels 2–5 add a perk, e.g. Arrow gets double arrows, piercing, crits and multishot |
| Enemy types | 10 | Includes the boss spawns stoneling and imp. Skeletons have a front shield, bats fly, shamans heal, summoners spawn |
| Bosses | 3 | 2–3 phases each, telegraphed attacks: charge, fire breath, tower disable |
| Upgrades | 46 | 16 common, 13 rare, 11 epic, 6 legendary. Weighted rarities |
| Synergies | 20 | Data-driven, e.g. Toxic Inferno, Shatter, Thunderstorm, Venom Barrage, Napalm, Death Mark, Arcane Storm |
| Random events | 5 | Treasure, Elite, Merchant, Mystery Chest, Cursed |
| Permanent upgrades | 10 | Bought with gold between runs |
| Achievements | 32 | |

Also included: tower unlocks for gems (lightning, fire, poison, sniper, magic; arrow, cannon and frost are free), a tower loadout of up to 4 towers (at least 3, must include an anti-air tower), a deterministic daily challenge with 2 of 14 modifiers, lifetime statistics, a tower collection and a bestiary.

Effects are composable data (stat, global, flag and instant effects). The simulation implements about 35 flags, with caps against runaway combos: a chance cap, a slow cap, a proc recursion guard and a chain cap of 25.

## Commands

Run these in `tower-merge/`.

| Command | Does |
|---|---|
| `npm install` | Installs dependencies |
| `npm run dev` | Starts the Vite dev server |
| `npm run build` | Writes the sprite manifest, typechecks and builds |
| `npm test` | Runs the 467 unit tests (vitest) |
| `npm run sim` | Headless bot balance simulations. Flags: `--runs`, `--policy`, `--pool`, `--meta`, `--probe loadout`, `--abilities`. See [docs/BALANCE.md](docs/BALANCE.md) |
| `npm run perf` | Simulation performance measurement |
| `npm run smoke` | Playwright end-to-end run against the Vite dev server (about 8 min). Covers menu, play, mouse and real CDP touch-drag merges, waves with upgrades and events until defeat, game over, play again, daily challenge, on 3 viewports including landscape. Fails on console errors |
| `npm run package` | Builds, validates against the Playables rules and writes `release/tower-merge-playables.zip` (1.38 MiB, 165 files) |
| `npm run sprites` | Regenerates the sprite manifest |

Art is generated by Node scripts in `tools/art/`. For example `node tools/art/towers.mjs && node tools/art/misc.mjs`, plus `creatures.mjs`, `icons.mjs` and `bg.mjs`. Contact sheets are written by `contact-sheet.mjs` and `sheet-creatures.mjs`. See [docs/ART_STYLE.md](docs/ART_STYLE.md).

## Architecture

- The simulation in `src/sim/` has no Phaser dependency. It is tested headlessly and balanced with bots.
- Phaser scenes only render the simulation and forward input. `api.ts` exposes pooled entity arrays and a drained event queue.
- Content is data, built from the shared contracts in `src/data/types.ts`.
- Presentation is kept apart from rules: `src/game/play/` holds the gameplay views (BoardView, TowerView, DragController, MergeFx, EnemyView, ProjectileView, Effects, DamageNumbers, Telegraphs, Hud, ShopBar, BossBar, Tutorial).
- Saves are versioned and migrated. Rewards are idempotent and nonce-checked.

## Performance

- Simulation, headless, 150 enemies and 12 level-5 towers: 0.18 ms average and 0.49 ms p95 per update, about 3 KiB of garbage per update.
- Sprites are pooled. Particles, flashes and damage numbers are capped. Quality degrades automatically below about 48 fps.

## Balance

Greedy bot median wave on a fresh save is 11 (about 5.6 minutes). Mid meta reaches 16, late meta 21, maxed 26. A never-merge policy reaches only wave 6 on a fresh save. The Dragon kills 23% of mid-meta runs that reach it. Across all 70 four-tower loadouts there is no dominant loadout, and every tower appears in a competitive one. Details in [docs/BALANCE.md](docs/BALANCE.md).

## Platform and rewards

- The Playables SDK script loads first in `index.html`. Assets and paths are relative. There are no external network requests.
- Saves go through `ytgame.game.saveData` inside Playables and localStorage in browsers.
- Pause only happens through `ytgame` `onPause` and `onResume`. Phaser's visibility listener is dropped inside Playables. Audio follows `isAudioEnabled`. The mute toggle is hidden on YouTube.
- Rewards: placements revive (once per run), rareTower (once per boss), reroll (once per upgrade screen), doubleGems (once per run) and emergencyPower (once per run). Claims are idempotent, nonce-checked and stored in the save, with daily caps. The game loop and audio pause during ads.
- `ytgame.ads.requestRewardedAd` was verified on 2026-10-18 to be available for Playables. It must be enabled in the Developer Portal monetization settings. `REWARD_CONFIG.youtubeAdsEnabled` is `false`, so the YouTube build offers a gem price instead. doubleGems has no gem alternative and is hidden without ads.
- Dev builds and `?mockads=1` use the mock ad provider.
- No reward is needed to progress.
